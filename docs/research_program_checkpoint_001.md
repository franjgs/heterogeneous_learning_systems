# Research Programme Checkpoint 001

> **Historical checkpoint.** It preserves the programme state at the time. Any RQ wording in this document is historical; the current canonical RQ0 is in [research_questions.md](research_questions.md).

## From heterogeneous routing and knowledge transfer to competence-improvement decisions

### 1. Original research question

The programme started from the following broad question:

> “How should a heterogeneous system dynamically allocate tasks among models/agents while simultaneously deciding how to redistribute the knowledge generated by those executions so that the system deliberately evolves its division of competences?”

This remains the broad motivating question. It does not replace the repository's current official RQ0, which remains unchanged in [research_questions.md](research_questions.md). RQ0 remains the sole promoted repository research question.

The central feedback loop under investigation is:

```text
routing
    -> operational experience
    -> learning / knowledge transfer
    -> competence change
    -> future routing
```

A provisional representation of system competence is a competence landscape:

```text
C_t = [c_iz(t)]
```

where `c_iz(t)` denotes the effective competence of model/agent `i` in task region or task family `z`. This representation is provisional: competence may not be directly observable, and this matrix may not ultimately be a sufficient state representation.

### 2. First concrete adversary: RouteNLP

RouteNLP is the strongest direct operational precedent identified so far. It already closes part of the loop:

```text
routing failures/escalations
    -> targeted distillation
    -> cheaper models change
    -> router is retrained/recalibrated
    -> routing changes
```

Its targeted-distillation heuristic ranks failure clusters approximately using:

```text
S_RouteNLP(z) = N_z * mean(Delta q_z)
```

That is, cluster frequency/size times average quality gap.

RouteNLP provides empirical evidence that operational routing experience can be used to modify the model portfolio and that this modification can improve subsequent routing economics. Therefore, this general closed-loop idea must not be claimed as novel.

The narrower open question is whether failure frequency and quality gap are sufficient information for deciding which competence-improvement actions are worth performing.

### 3. Working hypothesis H1

The first specific falsifiable working hypothesis is H1. It is not yet an official repository RQ and does not replace RQ0.

> **H1.** “Failure frequency and quality gap are insufficient statistics for selecting competence-improvement actions in a heterogeneous model portfolio. A useful selection policy should account for the expected learnability of the recipient model and the downstream operational value created by the competence change.”

The RouteNLP baseline/adversary is:

```text
frequency * quality_gap
```

A provisional conceptual alternative is:

```text
frequency
    * probability_of_successful_learning
    * downstream_operational_value
    - learning_cost
```

or, using model `i` and competence/task region `z`:

```text
V(i,z)
    ~ N_z
      * P_learn(i,z)
      * V_downstream(i,z)
      - C_learn(i,z)
```

This is a conceptual decomposition, not a proposed algorithm, theorem, or established optimal value function. Its purpose is to expose potentially missing variables.

### 4. Interpretation of the components

`P_learn(i,z)` is the expected learnability of competence `z` by recipient `i`.

`C_learn(i,z)` is the cost of producing the competence change. It may include data generation, teacher inference, fine-tuning, compute, latency, and related costs.

`V_downstream(i,z)` is the value created for future operation of the whole heterogeneous system after the competence of `i` changes. It is not simply the local accuracy improvement of learner `i`. It may alter:

- future routing decisions;
- inference cost;
- quality;
- latency;
- specialization;
- coverage;
- complementarity;
- redundancy;
- adaptability to future tasks;
- forgetting or interference in other competences.

This does not assert that all of these terms must appear in a final formulation.

### 5. Machine Teaching: what has been learned so far

The current conclusion from the Machine Teaching audit is that Machine Teaching already provides substantial precedent for:

- teaching actions conditioned on learner state;
- iterative/sequential teaching;
- estimating or handling partially unknown learners;
- heterogeneous learners;
- teaching cost/budget;
- optimizing teaching trajectories toward a desired target.

Therefore, none of these ingredients should independently be claimed as novel.

The important structural distinction identified so far is:

```text
Typical Machine Teaching:

    desired target competence is given
        -> determine how to induce it efficiently

Candidate system-level problem here:

    determine which competence is worth creating
        -> determine in which learner
        -> because of its future value to the whole operational system
        -> then use teaching/distillation mechanisms to realize that change
```

This does not claim that Machine Teaching cannot solve the latter problem. The papers examined so far primarily optimize teaching toward a specified target. A targeted literature audit is still required to determine whether Machine Teaching or adjacent areas already optimize target/task/competence selection according to downstream system utility.

Pending searches are:

- target selection in Machine Teaching;
- task/concept selection;
- multi-task Machine Teaching;
- curriculum across concepts;
- downstream-utility-aware teaching;
- expected return/value of a teaching intervention;
- competence acquisition under heterogeneous learners.

### 6. Diversity and Quality-Diversity: role in H1

Diversity is a possible component of `V_downstream`, not a separate research programme. Two competence-improvement actions producing similar local learner gains may have different system-level value because they leave different competence structures in the portfolio.

For example, teaching competence `z` to one model may duplicate an existing specialist, provide useful redundancy, or increase depth. Teaching it to another may increase complementarity, expand coverage, or preserve a broader repertoire.

Quality-Diversity provides established evidence that diverse repertoires can improve adaptability to contingencies and that maintaining diversity also has costs. Therefore, “diversity is valuable” must not be claimed as novel.

The more specific unresolved possibility is that competence diversity affects the downstream value of a teaching action under uncertainty about future task demand. The programme should not simply define an objective of the form `J + lambda * Diversity` unless later evidence justifies it. The preferred conceptual interpretation is that any value of diversity should, if possible, emerge from future system utility:

```text
V(C_t)
    = E_future_task_demand[
          future operational utility | C_t
      ]
```

The following are hypotheses/inferences, not established results:

```text
stable/predictable demand
    may favor greater specialization

uncertain/non-stationary demand
    may increase the option value of complementary competence
```

They are not laws.

### 7. Important methodological constraint

The research goal is not to find whether another paper contains similar terminology. For every adjacent field or paper, the audit must determine:

1. What exact problem is optimized?
2. What is the decision variable?
3. What is the objective/value function?
4. What information is assumed known?
5. What is learned or estimated?
6. What assumptions are required?
7. What theoretical guarantees exist?
8. What is actually demonstrated experimentally?
9. What limitations are acknowledged or observable?
10. Which part of H1 does it solve?
11. What does it not establish?

A similar abstract, terminology, or mathematical appearance is only a precedent, not evidence that the research problem is solved. Recent related work should normally be interpreted as evidence that an area is active unless its results genuinely reduce or solve the proposed problem.

### 8. Research programme from H1

The current planned audit sequence is:

1. **Active Learning / Value of Information / Experimental Design**

   Purpose: understand how existing theory values paying now for information because it improves future decisions.

   Extract:

   - expected value of information;
   - expected error reduction;
   - expected model change;
   - decision-theoretic active learning;
   - approximations used when exact future value is intractable.

   Central question: can these ideas value an action that changes model competence and therefore changes future routing?

2. **Machine Teaching / Curriculum Learning**

   Purpose: understand learnability, teaching cost, expected competence change, and whether target competence itself can be selected based on downstream utility.

3. **Bandits / Resource Allocation**

   Purpose: understand how to allocate limited learning budget among uncertain competence-improvement opportunities and whether learnability itself can be learned through exploration.

4. **Optimal Control / Maintenance / Capacity Expansion**

   Purpose: study the generic structure:

   ```text
   pay now
       -> change a system capability
       -> alter future operating costs and opportunities
   ```

Quality-Diversity remains a transversal source for understanding possible portfolio-level effects inside `V_downstream`, not a replacement for this programme.

### 9. What is NOT established yet

The programme currently does not establish:

- novelty of H1;
- optimality of the conceptual `V(i,z)` expression;
- multiplicative interaction among its terms;
- a valid observable competence representation `C_t`;
- how `P_learn` should be estimated;
- how downstream value should be estimated;
- that diversity should explicitly enter the objective;
- that more uncertainty necessarily implies more diversity;
- that competence diversity improves real LLM/SLM portfolios;
- that RouteNLP is suboptimal in realistic deployments;
- that a practical algorithm can outperform RouteNLP.

These are research questions and hypotheses to test.

### 10. Falsification philosophy

The programme should be killed or substantially redirected if literature or experiments show that:

- H1 reduces to an already mature solution with no meaningful remaining scientific dimension;
- `frequency * quality_gap` is already effectively sufficient under realistic conditions;
- learnability-aware selection produces no robust gain;
- future-system-value-aware selection produces no robust gain;
- the added complexity cannot outperform simpler heuristics after accounting for training and estimation cost.

A negative result reached early is considered useful.

### 11. Current scientific position

The broad research programme remains open.

The first concrete testable problem is no longer simply joint routing and knowledge transfer. It is whether competence-improvement actions in an operational heterogeneous model portfolio should be selected according to their expected future system value rather than only according to observed routing failures.

RouteNLP is the primary concrete adversary. Machine Teaching currently appears to provide mechanisms and theory for estimating the cost and effect of teaching, while Quality-Diversity motivates possible portfolio-level consequences of competence changes.

The immediate next research step is to investigate Active Learning / Value of Information / Experimental Design while continuing a targeted search within Machine Teaching for target/task selection based on downstream utility.
