# HLS Historical Memory and Novelty Guard

**Status:** PROTOCOL / SUPPORTING historical-memory instrument. It is not a
scientific theory, current-state authority, or substitute for the sources it
links. Its job is to prevent duplicate work and to make genuinely open
territory visible.

**Read with:** [Research Doctrine](../RESEARCH_DOCTRINE.md),
[HLS Current State](HLS_CURRENT_STATE.md), [Scientific History](HISTORY.md),
and [Repository Guide](REPOSITORY_GUIDE.md).

## 1. Operating rule

Before authorizing a synthetic scenario, mechanism, score, policy, learning
law, or experimental campaign, the Chief Engineer (CE) must answer:

1. What exact phenomenon is under investigation?
2. What is the closest historical HLS construction?
3. What **new** mathematical, causal, informational, organizational, or
   physical dependency is introduced?
4. Why cannot G2, MIS, G3, G3-H, or the recorded reductions already answer
   it?
5. What established result will be reused rather than rediscovered?
6. What genuinely new result would justify retaining the work?
7. What outcome triggers **STOP / REDUCTION**?

If questions 3 and 4 do not have precise, source-backed answers, the default
decision is **NO NEW SCENARIO**. A new name, visualization, parameterization,
or cleaner control is not by itself a new dependency.

The CE remains the scientific decision maker. This guard may identify a
historical analogue or an authority conflict; it may not settle a scientific
disagreement, promote exploratory evidence, or override a PI decision.

| Best current USE need not be best intertemporal action. | **CANONICAL**: G2 D2; MIS S3. | Do not reopen “can development make non-greedy action optimal?” as a new question. |

| Placement, gaps, substitution, comparative advantage, and feasible alternatives affect `D`. | **CANONICAL**: G3. | A placement-value claim must identify what it adds beyond this result. |

## 4. Adversarial novelty review

For a proposed direction, return this record before designing it:

```text
CLOSEST HISTORICAL ANALOGUE:
SAME DEPENDENCIES:
ACTUALLY NEW DEPENDENCIES:
WHAT WOULD BE REDISCOVERED:
WHAT EXISTING HLS CANNOT ANSWER:
NOVELTY VERDICT: REPEAT | REFRAMING ONLY | PARTIAL NOVELTY |
                 GENUINELY NEW DIRECTION | UNCLEAR
STOP / REDUCTION CONDITION:
```

Test explicitly whether the proposal is merely a renamed form of assignment,
present/future trade-off, learning by doing, continuation value, Bellman
optimization, placement value, sensitivity, separability, information sharing,
or standard exploration/exploitation. Flag, where applicable:

- **CIRCULAR REASONING** — exact validation reconstructs the quantity the rule
  was meant to avoid;
- **TERMINOLOGY DRIFT** — a new label denotes an old dependency;
- **TOY-MODEL DRIFT** — a new world precedes a novelty case;
- **MECHANISM FIXATION** — a mechanism is optimized before the question is
  shown to matter;
- **HISTORY FIXATION** — a genuinely new question is rejected only because it
  is not expressible in an old toy world;
- **CLAIM INFLATION** — exploratory evidence is narrated as theory; or
- **BASELINE WEAKNESS** — advantage comes only from restricting the comparator.

After a reduction, ask: **what scientifically important question cannot the
existing HLS machinery answer?** Novelty can lie in a new explanandum or a
new dependency, not merely in parameters, horizon, population size, geometry,
or a renamed score.

## 5. Current configuration × environment gap analysis

**Working direction, not established theory:** given known USE--DEVELOP
conflict, characterize which collective capability configurations perform
better in which environments, and how development changes that comparison.
Capability uncertainty / **DISCOVER** is not part of this initial object; it
requires a separate novelty review before introduction.

| Object | Already reusable | Missing from the recorded canonical construction |
| --- | --- | --- |
| Configuration | G1 supplies equal-resource static controls; MIS/G2/G3/G3-H accept heterogeneous interior states; `C(alpha)` preserves stated aggregate competence geometry. | A declared, common 3-worker × 2-capability family comparing generalist, specialist, and diverse configurations under a common budget convention. |
| Environment | G1 varies demand; MIS varies present/future demand; G2 varies terminal demand; RQ0 contains opportunity histories. | A predeclared small deterministic environment family expressly intended to compare configuration ranking across stable-balanced, stable-skewed, and shift conditions. |
| Development physics | MIS/G3/G3-H provide action-conditioned, saturating diminishing learning by doing; no uncertainty is required. | Nothing physical is required before reuse; any departure must state a missing dependency. |
| Performance and policies | Existing worlds provide immediate reward, terminal/continuation value, two-stage objectives, and exact DP/look-ahead comparators. | A single common configuration-by-environment value ledger with a strong fair USE baseline and a learning-disabled ablation. |

Thus the potential new object is **not** whether non-greedy development can be
optimal, nor whether placement has value. It is the comparative
configuration-by-environment performance relation under a declared common
world and ablations. Until that relation is specified, this is **PARTIAL
NOVELTY**, not an authorization for a new mechanism or a claim of adaptive
configuration value.

## 6. Authority and escalation

Use the current-status and authority documents to resolve priority; use this
guard to locate precedent. If sources materially conflict, if a proposed
dependency cannot be stated, or if an exploratory result is needed as a
premise, stop and escalate to the CE or PI. Chat summaries do not override
repository sources.
