# B2.2 PACS operational opportunity-value protocol

**Status:** PREREGISTERED — NOT EXECUTED. This document freezes the B2.2
design before any B2.2 training or result inspection. It adds no empirical
result, theoretical result, novelty claim, or B2.3 design.

## 1. Scientific question and scope

> Can an operational action that is inferior for the current task become
> preferable because it creates a learning opportunity whose future system
> value exceeds its current operational sacrifice?

B2.2 tests whether this minimal mechanism occurs empirically:

```text
operation
    -> learning opportunity
    -> competence development
    -> future operational value.
```

It does not test an end-to-end predictive HLS policy. Its narrower purpose is
to determine whether the mechanism that could justify such a policy exists
under the frozen intervention and valuation below.

## 2. Frozen system

B2.2 retains the B2.1 PACS system without model or split changes:

- Fast/student \(F\): ImageNet-pretrained MobileNetV2;
- Deep/teacher \(D\): ImageNet-pretrained ResNet-50;
- competence-profile axes, in fixed order: `photo`, `art_painting`,
  `cartoon`, `sketch`;
- \(F_0\): the B2.1 25%-BASE configuration for the corresponding seed;
- seeds: \(\{0,1,2,3,4\}\);
- device: CPU;
- the same PACS manifests, BASE/TRANSFER/VALIDATION memberships, transforms,
  model initialization, pseudo-labeling, optimizer, and three-epoch singleton
  update procedure as B2.1;
- VALIDATION supplies all decisions and reported competence scores;
- TEST remains closed and inaccessible.

Validation domain balanced accuracy is the declared empirical score on each
competence-profile axis. It does not identify latent competence \(S\) with
observed quality.

## 3. Operational action gates the opportunity

For a current task batch from domain \(k\), the operational action is
\(a\in\{F,D\}\):

- \(a=F\): \(F\) handles the batch, \(D\) is not queried, no Deep
  pseudo-label is generated, and no transfer opportunity exists;
- \(a=D\): \(D\) handles the batch, its hard pseudo-label is generated for
  each processed example, and an opportunity to update \(F\) becomes
  available.

Thus the feasible development sets are

\[
\mathcal D(F)=\{0\},\qquad \mathcal D(D)=\{0,1\}.
\]

This gate is part of the experimental treatment, not a post-hoc label. An
implementation is invalid if it queries \(D\) later for an example whose
recorded operational action was \(F\).

The actions remain distinct in the HLS ontology: \(a=D\) creates the
opportunity, while \(d=1\) uses it. Neither action is itself experience or a
competence change.

## 4. Paired two-stage counterfactual

For every seed, domain \(k\), and budget \(N\), both trajectories start from
the same \(F_0\) checkpoint and the same selected TRANSFER-example IDs.

The separated trajectory is

\[
F_0\xrightarrow{a=F}F_0.
\]

It contains no call to \(D\), no pseudo-labels, and no student update.

The HLS-candidate trajectory is

\[
F_0\xrightarrow{a=D,\ d=1}F_k.
\]

Exactly the \(N\) selected examples from domain \(k\) are processed by
\(D\). Their \(N\) hard pseudo-labels are the complete update set for
producing \(F_k\). The update begins directly from \(F_0\), uses the B2.1
singleton rule, and cannot begin from any other intervened state.

## 5. Current operational sacrifice

For current domain \(k\), define

\[
U_F(k)=S_k(F_0),\qquad U_D(k;c)=S_k(D)-c,
\]

and

\[
\rho_k(c)=U_F(k)-U_D(k;c).
\]

The primary scientific region requires the strict condition
\(\rho_k(c)>0\): Fast is preferred for current operation, so choosing Deep
incurs current operational sacrifice \(\rho_k(c)\). At \(\rho_k(c)=0\), the
current actions tie and the observation does not satisfy the primary event.

## 6. Future system value

The learning effect is evaluated on the complete four-domain competence
profile. With \(p_j=1/4\),

\[
V(F;c)=\sum_jp_j\max\{S_j(F),S_j(D)-c\}.
\]

The future-value change generated by the opportunity is

\[
\Delta V_k(c)=V(F_k;c)-V(F_0;c).
\]

For effective future-use weight \(B\) and development cost \(\kappa\), define

\[
\Omega_k(c,B,\kappa)=-\kappa+B\Delta V_k(c),
\]

\[
H_k(c,B,\kappa)=-\rho_k(c)+\Omega_k(c,B,\kappa).
\]

The symbol \(B\) is used deliberately: it is the effective number or weight
of future uses represented by the continuation calculation, not a discount
factor and not the theoretical note's \(\beta\).

### Mapping to the theoretical opportunity value

The preregistered \(\Omega_k\) above is the incremental value of **using** the
enabled opportunity, \(d=1\). The theoretical \(\Omega(S,q,D)\) optimizes over
\(\mathcal D(D)=\{0,1\}\), including no use, and therefore corresponds here to

\[
\Omega(S,q,D)=\max\{0,\Omega_k(c,B,\kappa)\},
\qquad \Omega(S,q,F)=0.
\]

This distinction preserves the theoretical nonnegativity of optimized
opportunity value while retaining the prescribed candidate-trajectory value
in \(H_k\).

For Q6, the contribution of each future domain \(j\) is also retained:

\[
\delta V_{k\to j}(c)=p_j\left[
\max\{S_j(F_k),S_j(D)-c\}
-\max\{S_j(F_0),S_j(D)-c\}
\right].
\]

Then

\[
\Delta V_k(c)=\sum_j\delta V_{k\to j}(c),
\]

with local contribution \(\delta V_{k\to k}\) and cross-domain contribution
\(\sum_{j\ne k}\delta V_{k\to j}\). These are descriptive decompositions of
the same frozen value function.

## 7. Primary test and exact frontier

The primary event for an individual observation is

\[
\boxed{\rho_k(c)>0\quad\text{and}\quad H_k(c,B,\kappa)>0.}
\]

It means that Fast is better for the current task, while choosing Deep and
using the opportunity has higher total value under the declared continuation
weight. Algebraically, the exact frontier is

\[
\boxed{B\Delta V_k(c)>\rho_k(c)+\kappa.}
\]

The complementary primary-region outcome

\[
\rho_k(c)>0\quad\text{and}\quad H_k(c,B,\kappa)\le0
\]

must be retained and reported. It identifies predeclared settings in which
integration does not compensate the current sacrifice.

For recorded decisions:

- current preferred action is `F` if \(\rho_k(c)>0\), `D` if
  \(\rho_k(c)<0\), and `TIE` if \(\rho_k(c)=0\);
- total-value preferred trajectory is `D+learning` if \(H_k>0\), `F` if
  \(H_k<0\), and `TIE` if \(H_k=0\);
- `integration_changes_decision` is true exactly when
  \(\rho_k(c)>0\) and \(H_k(c,B,\kappa)>0\).

All strict comparisons use the stored unrounded values.

## 8. Frozen grid

The complete primary grid is

\[
N\in\{25,50,100\},
\]

\[
c\in\{0,0.02,0.05,0.10,0.15\},
\]

\[
B\in\{1,2,5,10\},
\qquad \kappa=0.
\]

No value of \(N\), \(c\), or \(B\) may be selected retrospectively. The grid
contains \(5\times4\times3\times5\times4=1{,}200\) reported
seed-domain-budget-cost-future-weight observations. A later analysis with
\(\kappa>0\) would be secondary and requires a separate amendment that freezes
its values before execution; it is not part of this protocol.

## 9. Mandatory implementation controls

Before any scientific classification, the implementation must verify and
record that:

1. the `F` trajectory made zero calls to the Deep pseudo-label function and
   produced zero Deep pseudo-labels;
2. the `D+learning` trajectory used exactly \(N\) hard pseudo-labels generated
   by \(D\) for the recorded \(N\) TRANSFER IDs from domain \(k\);
3. both trajectories reference the same seed-specific \(F_0\) state-dict
   fingerprint before the action;
4. \(F_k\) was updated directly from that \(F_0\), without another
   intervention state;
5. BASE, TRANSFER, and VALIDATION IDs retain their B2.1 roles and are
   disjoint;
6. no TEST ID, label, prediction, score, or model-selection signal was read;
7. \(S(F_0)\), \(S(F_k)\), and \(S(D)\) each contain exactly the four fixed
   PACS-domain validation scores;
8. \(V\), \(\Delta V\), \(\Omega\), and \(H\) recompute exactly from stored
   unrounded component values and the frozen formulas;
9. the result contains all 1,200 unique grid observations and no unexpected
   duplicates or missing values.

A failure of these controls invalidates the run for scientific classification;
it is not a NULL result.

## 10. Primary outputs

For every seed, domain, \(N\), \(c\), and \(B\), store at least:

- seed, domain, \(N\), \(c\), \(B\), and \(\kappa\);
- the four-component vectors \(S(F_0)\), \(S(F_k)\), and \(S(D)\);
- the selected TRANSFER IDs and their action/provenance record;
- the common initial \(F_0\) fingerprint and the resulting \(F_k\)
  fingerprint;
- Deep-query count and pseudo-label count for both trajectories;
- \(U_F(k)\), \(U_D(k;c)\), and \(\rho_k(c)\);
- \(V(F_0;c)\), \(V(F_k;c)\), \(\Delta V_k(c)\), \(\Omega_k\), and \(H_k\);
- all four \(\delta V_{k\to j}(c)\) contributions and their local/cross-domain
  sums;
- current preferred action and total-value preferred trajectory;
- `integration_changes_decision`.

## 11. Aggregate questions and reporting

B2.2 must report, without retrospective grid selection:

1. whether any observations satisfy \(\rho>0,H>0\);
2. for every exact domain-\(N\)-\(c\)-\(B\) cell, how many of five seeds
   satisfy the event;
3. where \(\rho>0,H\le0\) occurs;
4. whether every stored event agrees exactly with
   \(B\Delta V>\rho+\kappa\);
5. how the event region changes descriptively with \(N\), \(c\), and \(B\);
6. the local and cross-domain components of \(\Delta V\);
7. the number and fraction of the 1,200 observations for which internalizing
   opportunity value changes the operational decision.

No inferential significance test is preregistered. Seed counts and all grid
cells must be shown; isolated favorable cases cannot be promoted as the main
result.

## 12. Frozen outcome classification

The following rules cannot be changed after results are observed.

### POSITIVE

B2.2 is `POSITIVE` if all validity controls pass and both conditions hold:

1. at least one exact domain-\(N\)-\(c\)-\(B\) cell satisfies
   \(\rho>0,H>0\) in at least two of the five seeds; and
2. at least one exact grid cell satisfies \(\rho>0,H\le0\) in at least two
   seeds.

This requires a reproducible favorable region and a reproducible region in
which the current sacrifice is not compensated, rather than a universal
advantage.

### NULL

B2.2 is `NULL` if all validity controls pass and no observation anywhere in
the predeclared grid satisfies \(\rho>0,H>0\).

### INCONCLUSIVE

B2.2 is `INCONCLUSIVE` if all validity controls pass but it is neither
`POSITIVE` nor `NULL`: for example, favorable observations occur only in an
isolated seed, or the favorable/noncompensating regions do not meet the frozen
cross-seed reproducibility requirement.

## 13. Permitted and prohibited claims

A `POSITIVE` result permits the following scoped statement:

> An operationally inferior action can generate a learning opportunity whose
> future system value exceeds its immediate operational sacrifice under
> empirically realized conditions.

It would support the empirical chain

```text
operation
    -> learning opportunity
    -> competence change
    -> future operational value.
```

Even a `POSITIVE` result does not establish:

- that an implementable HLS policy can predict \(\Omega\) ex ante;
- universal superiority over separated architectures;
- causal superiority beyond the defined intervention;
- superiority or generalization on TEST;
- full closed-loop validation of RQ0;
- novelty.

## 14. Relation to B2.1 and RQ0

B2.1 supplied validation-only evidence for

```text
learning -> competence changes -> future operational organization/value.
```

B2.2 tests the other connection by making opportunity availability depend on
the recorded operational action:

```text
operation
    -> availability of learning opportunity
    -> competence changes
    -> future operational value.
```

A `POSITIVE` B2.2 would support the central mechanism of RQ0. It would not
answer RQ0 completely because no ex-ante closed-loop policy is learned or
compared with a scientifically strong separated baseline.

## 15. Execution boundary

This protocol authorizes no training or result generation. Before execution,
the implementation must encode the action gate and controls above without
changing this scientific design. TEST must remain closed. No B2.3 design is
part of this document.
